VIGIL --- Orbital Debris Detection & Tracking

VIGIL is a research and development platform for inspecting ground-based
optical telescope imagery and analyzing potential orbital-debris
candidates.

The project brings together image inspection, candidate detection,
multi-frame tracking, and visualization in a scientific
workstation-style interface. Its purpose is to help users investigate
faint streaks and other image features that may warrant further
analysis.

Scientific note: A detected image feature is not automatically
confirmed orbital debris. Detection, tracking, and trajectory results
must be evaluated against suitable reference data. Describe features
as operational only when they have been implemented and verified.

Project Goals

Inspect telescope image frames and validate frame stacks.

Identify candidate image features using the available processing
pipeline.

Explore detections across multiple frames when tracking is
available.

Visualize simulation outputs and evaluation results when present.

Provide a clear interface for reviewing source images and analysis
outputs.

Features

These are project capabilities and intended interface areas;
availability depends on the current implementation and its validation
status.

Image analysis: inspect telescope frames and relevant image
properties.

Frame-stack ingestion: select and validate compatible image
sequences.

Detection visualization: view candidate detections and overlays
when generated by the pipeline.

Multi-frame tracking: review track associations when supported
by the implementation.

Trajectory analysis: display trajectory estimates only when the
required algorithm and data are available.

Simulation results: inspect existing outputs stored in
data/results, where supported.

Demonstration media: present project video and supporting images
stored under assets/matlab-demo, if present.

Getting Started

1. Clone the repository

git clone <YOUR_REPOSITORY_URL>
cd debris-tracker-main

Replace <YOUR_REPOSITORY_URL> with the repository's actual Git URL.

2. Inspect the project

Review the repository files and dependency manifests. Confirm the
available frontend, backend, MATLAB entry point, datasets, and test
commands.

3. Run the Python backend (if included)

If run_server.py is present and its dependencies are installed, try:

python run_server.py

Use the port and startup instructions printed by the application. Do not
assume a particular address until startup succeeds.

4. Run the MATLAB pipeline (if included)

Open MATLAB, set the Current Folder to the repository directory, and
inspect the intended entry point before execution. If main.m is the
verified entry point, run:

main

The pipeline may require the Image Processing Toolbox or other
dependencies. Check the source code, MATLAB version, toolbox
availability, and input paths first.

5. Run tests (if included)

If the repository contains a Python test suite and dependencies are
installed, a possible command is:

python -m pytest tests/ -v

Follow the actual test instructions in the repository. Passing tests do
not by themselves prove that the complete scientific pipeline has been
validated.

Data and Results

Supported Input Formats

Input formats depend on the loader in the current version. The MATLAB
loader may expect BMP frames; inspect the code before assuming support
for JPEG, PNG, or other formats. Validate frame dimensions, bit depth,
ordering, and other constraints before processing.

Validation and Limitations

Before presenting results, verify:

The pipeline executes successfully in the target environment.

Required functions, dependencies, and licenses are available.

Input frames are loaded in the intended order.

Detection and tracking outputs are generated by the actual code.

Metrics are calculated from identified reference data with
documented matching criteria.

The interface distinguishes saved results from new/live analysis.

Do not claim accuracy, real-time operation, official NASA validation, or
fully working advanced algorithms unless supported by reproducible
evidence.
